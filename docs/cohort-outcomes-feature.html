1. Purpose & Background

The professor needs to track alumni employment and course-alignment outcomes grouped by graduation cohort (batch year), not just by broad career stage buckets. The goal is to answer questions like:

  • "Batch 2018 — what is their employment status 5 years after graduation (2023)?"
  • "Batch 2019 — 5-year check-in is due in 2024. What is the current data?"
  • "Which cohort has the highest course-alignment rate?"
Important Design Decision The system stores only the current employment status of each alumni — there are no historical snapshots. Therefore, the table shows each cohort's current recorded status while framing it with a "5-Year Evaluation Year" column (batch year + 5) that tells the professor when a formal survey was due for that cohort.

The feature was added to three areas of the system: the Admin Dashboard, the Reports Page (UI table), and the PDF Export (Section C).

2. Key Concepts & Definitions

Batch Year

The year an alumni graduated (or the cohort year they are associated with). Stored as an integer in Firestore under the batchYear field on each user document.

5-Year Evaluation Year (Eval Year)

The year a cohort is due for a formal 5-year outcome survey, computed as:

Eval Year = Batch Year + 5

Example: Batch 2018 → Eval Year 2023. This matches the institution's survey cycle where graduates are formally tracked 5 years after their graduation.

Years Out

How many years have passed since the cohort's graduation as of the current year:

Years Out = Current Year − Batch Year

This gives context about how mature the cohort is (e.g., a batch year of 2020 is currently 6 years out in 2026).

Course-Aligned Employment

An alumni is considered course-aligned if they are both employed and their job is related to their engineering program. Alignment is determined by:

  1. Direct survey answer — if the alumni explicitly answered a courseAligned yes/no field in their profile, that answer takes priority.
  2. Keyword matching (fallback) — if no direct answer exists, the system checks the alumni's currentPosition job title against a predefined keyword list for their program (e.g., "logistics", "lean" for Industrial Engineering).
Why Survey Answer Takes Priority Keyword matching can produce false positives (e.g., a job title that mentions "industrial" but is unrelated to IE). When alumni explicitly confirm alignment, that signal is more accurate. Keyword matching serves as a fallback for older records.

3. Computation Logic

Step 1 — Group alumni by batch year

The function iterates over all alumni documents. Alumni with no batchYear are skipped. For each valid alumni, a running tally is maintained per batch year:

  • total — count of all alumni in that cohort
  • employed — count where isEmployed === true
  • aligned — count where the alumni is both employed and course-aligned (via the isAligned() helper)

Step 2 — Compute rates

Both rates are rounded to the nearest whole percent:

Employment Rate = round( employed / total × 100 )
Alignment Rate = round( aligned / total × 100 )
Denominator Note The Alignment Rate denominator is the full cohort (total), not just employed alumni. This means it represents the percentage of all graduates in that cohort who are both employed and in a course-aligned job — a more conservative and meaningful metric for accreditation purposes.

Step 3 — Sort and return

Rows are sorted newest batch year first (descending), so the most recent cohorts appear at the top of the table.

isAligned() Helper

This private function (in courseAlignment.ts) implements the alignment check:

function isAligned(a: AlumniForOutcome): boolean {
  if (!a.isEmployed) return false;          // not employed → never aligned
  if (typeof a.courseAligned === "boolean")  // explicit survey answer?
    return a.courseAligned;
  // fallback: keyword match on job title
  return isCourseAligned(a.currentPosition ?? "", a.course);
}

7. Core Utility: computeCohortBreakdown()

Located in src/lib/utils/courseAlignment.ts. Full implementation:

export interface CohortRow {
  batchYear:      number;   // graduation cohort year
  evalYear:       number;   // batchYear + 5
  yearsOut:       number;   // currentYear - batchYear
  total:          number;   // all alumni in cohort
  employed:       number;   // isEmployed === true
  employmentRate: number;   // % employed (0–100)
  aligned:        number;   // employed + course-aligned
  alignmentRate:  number;   // % aligned of total (0–100)
}

export function computeCohortBreakdown(
  alumni: AlumniForOutcome[]
): CohortRow[] {
  const currentYear = new Date().getFullYear();
  const map = new Map<number, { total: number; employed: number; aligned: number }>();

  for (const a of alumni) {
    if (!a.batchYear) continue;          // skip alumni with no batch year
    if (!map.has(a.batchYear))
      map.set(a.batchYear, { total: 0, employed: 0, aligned: 0 });
    const row = map.get(a.batchYear)!;
    row.total++;
    if (a.isEmployed === true) row.employed++;
    if (isAligned(a))              row.aligned++;
  }

  return Array.from(map.entries())
    .sort(([a], [b]) => b - a)           // newest batch year first
    .map(([batchYear, row]) => ({
      batchYear,
      evalYear:       batchYear + 5,
      yearsOut:       currentYear - batchYear,
      total:          row.total,
      employed:       row.employed,
      employmentRate: row.total > 0
        ? Math.round((row.employed / row.total) * 100)
        : 0,
      aligned:        row.aligned,
      alignmentRate:  row.total > 0
        ? Math.round((row.aligned / row.total) * 100)
        : 0,
    }));
}

Input type: AlumniForOutcome

FieldTypeUsage
batchYearnumber | nullGroups the alumni into a cohort row. Null → skipped.
coursestring | nullUsed by keyword-matching fallback for alignment.
isEmployedboolean | undefinedCounted toward employed.
currentPositionstring | undefinedJob title for keyword-matching alignment fallback.
courseAlignedboolean | undefinedExplicit survey answer for alignment (highest priority).

The PDF export in exportPDF() is structured in three sections on Page 1, followed by the Alumni Registry on Page 2+.

SectionContent
AEmployment Summary — Employed / Unemployed / Total with counts and rates
BCourse-Aligned Placement Rates — by career stage bucket (0–2 yrs, 3–5 yrs, 6+ yrs)

Placement in the PDF

// Section C starts immediately after Section B's last row
const afterB = (doc as any).lastAutoTable.finalY + 8;
doc.text("C. Cohort Outcomes by Batch Year", 14, afterB);
autoTable(doc, {
  startY: afterB + 3,
  head: [["Batch Year", "5-yr Eval Year", "Years Out",
          "Total", "Employed", "Employment Rate",
          "Course-Aligned", "Alignment Rate"]],
  body: cohortRows.map((row) => [
    String(row.batchYear),  String(row.evalYear),
    `${row.yearsOut} yrs`,  String(row.total),
    String(row.employed),   `${row.employmentRate}%`,
    String(row.aligned),    `${row.alignmentRate}%`,
  ]),
  styles:     { fontSize: 8 },
  headStyles: { fillColor: [30, 41, 82] },   // navy
  columnStyles: {
    5: { fontStyle: "bold" },   // Employment Rate — bold
    7: { fontStyle: "bold" },   // Alignment Rate — bold
  },
});
Page overflow behaviour jspdf-autotable automatically adds new pages if Section C overflows the first page. The footer note is fixed at y = 285 on page 1, so it may overlap the table if there are many batch year rows. This is acceptable for typical cohort sizes (< 20 rows).

11. Edge Cases & Limitations

ScenarioBehaviour
Alumni with no batchYear Skipped entirely — not included in any cohort row
Alumni with isEmployed not set (undefined) Not counted as employed; not counted as aligned
Cohort with 0 alumni (after filtering) No row produced (division by zero is guarded: rate returns 0)
Current year cohort (graduated this year) Years Out = 0, Eval Year = current year + 5; included normally
Future batch years in the database Years Out would be negative — included as-is; no filtering is applied
No alumni have batch years at all Dashboard: table card is not rendered (cohortRows.length === 0)
Keyword matching ambiguity Mitigated by prioritising the explicit courseAligned survey field
No Historical Snapshots Because the system only stores current status, the "5-Year Evaluation Year" column is informational only. The data shown for Batch 2018 reflects their status today, not what it was in 2023. Future versions may introduce snapshot storage to capture point-in-time data.
